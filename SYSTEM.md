# SYSTEM.md

> Версия: 1.0 Статус: Architectural Specification (Source of Truth)

# 1. Назначение

Данный документ является **единственным источником истины** относительно
архитектуры проекта.

Любые изменения архитектуры сначала отражаются здесь, затем реализуются
в коде.

Проект представляет собой платформу для воспроизводимого сравнения
алгоритмов кластеризации в централизованной и федеративной среде.

Flower используется исключительно как backend выполнения федеративных
экспериментов.

------------------------------------------------------------------------

# 2. Цели

Система должна:

-   запускать большое количество экспериментов автоматически;
-   одинаково запускать любые алгоритмы;
-   поддерживать централизованные и федеративные алгоритмы;
-   обеспечивать воспроизводимость;
-   автоматически считать метрики;
-   хранить результаты в едином формате;
-   легко расширяться.

Система **не занимается**:

-   разработкой новых алгоритмов;
-   обучением моделей вне эксперимента;
-   feature engineering;
-   хранением больших наборов данных.

------------------------------------------------------------------------

# 3. Архитектурные принципы

1.  Single Responsibility.
2.  Dependency Inversion.
3.  Plugin Architecture.
4.  Composition over inheritance.
5.  Low Coupling.
6.  High Cohesion.
7.  Reproducibility First.
8.  Framework Independence.

# 5. Основные сущности

## Dataset

Описывает источник данных.

Поля:

-   id
-   name
-   features
-   labels
-   metadata

Создается только DatasetRegistry.

------------------------------------------------------------------------

## Partition

Описывает распределение объектов между клиентами.

Типы:

-   IID
-   Dirichlet
-   Balanced
-   Pathological

------------------------------------------------------------------------

## Algorithm

Единица вычисления.

Алгоритм **не знает**, каким образом он запускается.

Контракт:

``` python
class ClusteringAlgorithm:
    def fit_predict(self, X):
        ...
```

Возвращает только метки кластеров.

Не имеет права:

-   сохранять файлы;
-   считать метрики;
-   обращаться к CLI.

------------------------------------------------------------------------

## Experiment

Минимальная независимая задача.

Содержит:

-   dataset
-   partition
-   algorithm
-   parameters
-   seed
-   execution backend

------------------------------------------------------------------------

## Result

Содержит:

-   предсказания;
-   значения метрик;
-   runtime;
-   служебные данные.

------------------------------------------------------------------------

# 6. Компоненты

## Dataset Registry

Ответственность:

-   загрузка;
-   регистрация;
-   кэширование;
-   выдача Dataset.

Не знает:

-   алгоритмов;
-   Flower;
-   метрик.

------------------------------------------------------------------------

## Partition Manager

Создает Partition.

Не знает:

-   алгоритмов;
-   Runner;
-   Flower.

------------------------------------------------------------------------

## Algorithm Registry

Источник истины относительно алгоритмов.

Регистрирует:

-   sklearn
-   Flower adapters
-   пользовательские реализации

Возвращает экземпляры по имени.

------------------------------------------------------------------------

## Experiment Planner

Получает:

-   список датасетов;
-   список алгоритмов;
-   параметры;
-   стратегии разбиения;
-   seed.

Строит декартово произведение.

На выходе --- список Experiment.

------------------------------------------------------------------------

## Execution Layer

Единственная задача --- выполнить Experiment.

Поддерживает реализации:

-   LocalExecution
-   FlowerExecution

Интерфейс:

``` python
class ExecutionBackend:
    def execute(experiment) -> Result:
        ...
```

------------------------------------------------------------------------

## Metrics Engine

Получает:

-   labels_true
-   labels_pred

Считает:

-   ARI
-   NMI
-   Silhouette
-   Davies--Bouldin
-   Calinski--Harabasz

Не выполняет алгоритмы.

------------------------------------------------------------------------

## Result Repository

Сохраняет результаты.

Формат:

results/ metrics.csv experiment.json predictions/ logs/

------------------------------------------------------------------------

# 7. Инварианты

Всегда должны соблюдаться.

1.  Algorithm никогда не вызывает Flower напрямую.
2.  Flower никогда не считает метрики.
3.  DatasetRegistry никогда не знает об алгоритмах.
4.  MetricsEngine никогда не запускает алгоритмы.
5.  Planner никогда не выполняет вычисления.
6.  Runner никогда не считает метрики.
7.  ResultRepository ничего не вычисляет.

------------------------------------------------------------------------

# 8. Последовательность выполнения

1.  CLI читает YAML.
2.  Создается ExperimentManager.
3.  DatasetRegistry загружает Dataset.
4.  PartitionManager строит Partition.
5.  Planner создает список Experiment.
6.  Runner берет следующий Experiment.
7.  AlgorithmRegistry создает Algorithm.
8.  ExecutionLayer запускает алгоритм.
9.  Получаются labels.
10. MetricsEngine вычисляет показатели.
11. ResultRepository сохраняет артефакты.
12. Следующий Experiment.

------------------------------------------------------------------------

# 10. Добавление нового алгоритма

Разрешается изменять:

-   algorithms/
-   configs/
-   tests/

Запрещается изменять:

-   planner
-   metrics
-   results
-   dataset registry

Алгоритм обязан поддерживать контракт `fit_predict()` либо предоставлять
адаптер.
