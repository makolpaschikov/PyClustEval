# История экспериментов MNIST 10k

Это результаты тех же 180 завершённых запусков, по которым составлен
`../MNIST_10k_comparison.docx`. Алгоритмы при экспорте не запускались заново.
Других датасетов в экспорте нет: каждый вход содержит 10 000 объектов × 784 признака.

- `report.json` — сводный JSON по всем 180 запускам с метриками, параметрами,
  числом сохранённых записей истории и ссылками на полные отчёты в архиве.
  Это коллекция экспериментов, а не один нативный ComparisonReport.
- `results.csv` — сводная таблица тех же измерений.
- `mnist10k_history.zip` — 23 сравнения (4 локальных алгоритма в одном сравнении
  и 22 федеративных сценария по 8 алгоритмов) в нативном формате PyClustEval.
  Для каждого сравнения есть `report.json`, `results.csv`, `execution.log`.
  Полные исходные model_state и history сохранены, включая центры на раундах.
  Архив также содержит предсказания всех 180 запусков, истинные метки,
  индексы выбранных изображений, разбиения клиентов, проверку MNIST и протокол.

## Как загрузить в приложение

1. Скачайте `mnist10k_history.zip` и распакуйте в корень PyClustEval.
2. Каталоги `history/YYYY-MM-DD_.../` должны оказаться непосредственно в
   папке `history/` проекта. Если распаковщик создал дополнительную папку,
   перенесите её содержимое в корень проекта.
3. Перезапустите приложение или обновите список истории. Появятся 23 сравнения
   с идентификаторами `mnist10k_baseline`, `mnist10k_iid_full` и т. д.

Те же каталоги можно читать программно:

```python
from clustering_eval.application import HistoryQueryService

history = HistoryQueryService("history")
for item in history.list_experiments():
    if item.dataset_name == "mnist_10k":
        details = history.get_experiment(item.history_key)
        print(item.experiment_id, len(details.results))
```

## Что именно записано

История восстановлена из исходных артефактов реальных worker-процессов.
Это не повторное исполнение через UI. Истории раундов сохранены только там,
где их действительно возвращал адаптер; пустые списки не дополнены выдуманными
раундами. ARI/AMI/NMI на каждом раунде в исходных запусках не измерялись:
они есть для окончательных предсказаний. Для некоторых методов на раундах
сохранялись shift/objective/inertia/центры и состав клиентов.

Исходный worker не записывал UTC-время начала/окончания в JSON. В нативной
истории эти даты ОЦЕНОЧНЫЕ: время изменения исходного JSON и записанное
`total_wall_sec`. Длительность сравнения — интервал между отдельными workers,
включая паузы и повторную проверку двух HF-запусков. Исходные измерения времени
каждого алгоритма сохранены точно в `runtime_sec`, а способ оценки дат указан
в `export_provenance` и `source_run`. Клиентские ARI/NMI рассчитаны при экспорте
по сохранённым предсказаниям; глобальные метрики взяты без изменений из запусков.

Неопределённые геометрические метрики записаны как JSON null. Авторские
DP-прокси явно помечены `[DP proxy]`. Ни метрики качества, ни весь этот отчёт
не являются DP-релизом. Трафик — логический payload, не сетевые пакеты.

В `mnist10k/source_changes.patch` лежат изменения к базовому коммиту
6c79b384e7537c4b94c6c1887ba36eceded7314c, использованные при вычислениях.
Версии кода и особенности протокола важны при воспроизведении результатов.

Разбор низкого качества находится в `quality_review.md`, дополнительные
контрольные прогоны — в `quality_diagnostics.json`. Они также включены в архив
в папку `mnist10k/`, отдельно от 180 исходных запусков и нативной истории.
