# Historical source used by the paper campaigns

The nine archived series used Git commit `6c79b384e7537c4b94c6c1887ba36eceded7314c` with local changes. The comparison checkout at `5d3723a08f8a7fe9003050923a66d705f1e77c09` contains the same committed bytes as that earlier commit on every audited path. Recovering the application that produced the archive requires both the historical commit and its patch. The archive also includes a separate worker, preparation scripts and environment data in `reproduce/`.

## Repeat the source check

From a PyClustEval checkout containing both Git commits, pass the path to the paper's `experiments` directory. The checker uses Git and the Python standard library.

```powershell
py -3.14 -B tools/check_campaign_source_baseline.py 'X:\path to paper\experiments'
```

The optional `--repo PATH` selects the working files independently of the script location. The checker reads three pinned historical artifacts from `reproduce/`.

| Artifact | SHA-256 |
| --- | --- |
| `source_snapshot.zip` | `6c04276c803018475602b78dfb8b7be3b23a2714c6ad1b2cce5b1ae9616ad3e5` |
| `source_changes.patch` | `844167891479ee9513d3ec8b5fcd156649f7f7977702a4f36215281ed531d073` |
| `source_code_verification.json` | `fda5b129d9ee67d2d36cafa2c3ba83acf2411eafa66a6e194f21dd0c47899b96` |

The checker reconstructs the patched Git blobs in the index and object store of a temporary bare repository. The checkout supplies the original Git objects through a read-only alternate. No archived code is imported or executed. All 17 patch preimage and postimage IDs must match their declared prefixes. The checker compares each of the 79 ZIP members with its reconstructed blob, allowing only CRLF/LF normalization. The patch contains 15 of the ZIP paths and two additional tests.

For each ZIP member, the JSON report compares the archived bytes with the selected **working file** and returns `exact`, `eol_only`, `content` or `missing`. On the original Windows checkout the counts were 10 exact, 54 EOL-only, 15 content and 0 missing. Checkout line-ending settings can redistribute the 64 exact/EOL-only matches. All 81 audited working paths, including the two tests, are also compared directly with the pinned baseline. A later checkout can still differ from the archived ZIP on the original 15 paths while containing additional edits to one of those same files. The separate drift list catches that case. Exit code 0 requires the expected baseline. Drift yields JSON with `verified=false` and exit code 1. Unreadable or inconsistent evidence yields a diagnostic and exit code 1.

## Compatibility decisions by path

Here “baseline” refers to the comparison commit above and “archive” refers to the reconstructed postimage. Each decision assigns the difference to the stage that can evaluate it. This source audit establishes which code was present. The controls below require examination or execution when implementing the named stages.

| Changed path | Baseline and archive behavior | Decision and observable regression control |
| --- | --- | --- |
| `clustering_eval/algorithms/author_adapters.py` | Baseline calls the author HF_DBSCAN assignment even with zero server cells. The archive skips that pass and retains a full-length vector of noise labels. The nonempty-cell path and the earlier DP proxy branch are unchanged. | COMPUTE verifies all labels equal −1, round count and payload stay equal on an empty-cell control, and a nonempty control still assigns clusters. Measure the possible speedup separately. |
| `clustering_eval/federated/environment.py` | Baseline clamps out-of-range schedule access. The archive validates schedule entries and round budgets. Tolerance stopping requires a constant successful-client set across the budget and no positive aggregate noise sigma. Enabled DP budgets must cover the requested rounds. | COMPUTE checks short/malformed schedules, fixed versus changing successful sets, zero/positive sigma and an insufficient DP budget. The schedule generator itself has the same code. |
| `clustering_eval/algorithms/fed_kmeans_numpy.py` | Baseline applies the shift tolerance each round and accounts for downlink with nonempty successful clients. The archive applies the shared stopping rule, counts downlink to every selected client and counts uploads from successful nonempty clients. It also converts X to float64 and accepts the second K alias. | COMPUTE checks dtype and both K aliases, actual rounds and logical bytes under fixed and changing participation, including a selected dropout. Labels may change with the effective K or stopping round. |
| `clustering_eval/algorithms/federated_extra.py` | The same stopping and downlink changes affect NumPy FCM and GMM. Baseline GMM measures changes in means. The archive takes the maximum of the changes in means, variances and weights. | COMPUTE compares the two methods separately. Check stopping with stationary means and moving variances/weights, history shifts, logical bytes and reported convergence. |
| `clustering_eval/flower_adapter/fed_kmeans_flower_adapter.py` | Baseline records convergence while still configuring client fits. The archive stops dispatch after eligible convergence, handles the K alias and omits the inertia wire metric for aggregate DP. | COMPUTE/PROFILE checks update count, post-convergence dispatch/payload, presence of wire metrics and final labels in an actual Flower simulation. |
| `clustering_eval/flower_adapter/federated_extra_flower.py` | Baseline Flower FCM/GMM perform the full schedule. The archive adds convergence and dispatch guards, checks FCM fuzziness, uses all three changes for GMM, and omits the affected objective/likelihood wire metrics in aggregate DP. | COMPUTE/PROFILE exercises invalid fuzziness, changed successful-client sets, noise, GMM convergence and keys actually exchanged on the wire. Privacy effects require separate review. |
| `clustering_eval/privacy/aggregate_dp.py` | The archive adds a public fixed MNIST reference for the two MNIST names with 784 features (zero center, unit scale for normalized pixels). The baseline rejects that dataset in this path. | COMPUTE checks dimensionality, public reference metadata and resulting clipped input fingerprint on the intended pixel scale. The source change alone establishes no privacy guarantee. |
| `clustering_eval/application/comparison_service.py` | The archive resolves K aliases across parameter layers, validates effective round budgets before scheduling, sizes the common schedule for overrides and calibrates DP to effective rounds. It adds public MNIST K=10 and distinguishes requested and effective values in diagnostics. Baseline uses the common round budget in these paths. | COMPUTE checks alias precedence/conflicts, schedule length, effective K/rounds, calibrated budget and diagnostics. Keep legacy GUI behavior separately identifiable. The archived worker calls algorithms directly. |
| `clustering_eval/application/dto.py` | The archive rejects fractional/boolean round budgets, conflicting or invalid K aliases, reserved protocol overrides and nonfinite values in tolerance, epsilon and clipping. The baseline has weaker checks on these inputs. | PLAN/COMPUTE exercise valid inputs and each rejected class before computation. This request validator is outside the historical direct-worker path. |
| `clustering_eval/experiments/runner.py` | Baseline replaces false-valued Dirichlet alpha with 0.5. The archive defaults only on None and adds profile defaults before explicit algorithm overrides. | PLAN/COMPUTE preserve the legacy entry point and test None, zero and positive alpha, plus profile versus explicit parameter priority. Historical workers applied profile defaults separately. |
| `clustering_eval/results/excel_export.py` | The archive moves the runtime import of ComparisonReport under TYPE_CHECKING. The XLSX export body is unchanged. | EXPORT retains the behavior and checks the standalone import and representative workbook fields if adopting the import change. |
| `clustering_eval/results/history_store.py` | The archive makes ComparisonReport a type-only import. The history serialization and persistence bodies are unchanged. | EXPORT checks direct import and a native-history round trip, including stored model state. |
| `clustering_eval/results/public_release.py` | The archive makes the same type-only import change. The public-report filtering body is unchanged. | EXPORT checks the direct import and unchanged filtering on the same report. No broader privacy conclusion follows from the import change. |
| `README.md` in the source ZIP | The archive adds explanations of partition invariance, stopping policy and effective overrides, plus references to test modules outside the snapshot and patch. | Retain as historical documentation. COMPUTE checks each scientific claim against actual code and controls before adopting it. |
| `pyclusteval_ui.py` | The archive adds help text concerning similar ARI under full participation and adjusts its wrapping. The computation request and its parameters are unchanged. | Preserve current GUI behavior. A later wording change would require checking the full-participation/no-noise conditions and the displayed text. |

The two test files outside the snapshot have independently checked preimage and postimage Git IDs in the patch. `tests/test_author_adapters.py` adds line-ending normalization to the pinned p-FClus source hash. `tests/test_hfdbscan_compatibility_patch.py` adds a comparison with the author's noise assignment for empty server cells. Their presence in the patch records the proposed tests. This source check does not execute them.

The archived worker uses five adapted and three Flower federated methods. The NumPy federated changes therefore matter to new campaigns and backend comparisons. Source identity alone cannot establish that the historical worker exercised each modified path, that noisy runs reproduce labels, or that execution times on different runtimes are comparable.
